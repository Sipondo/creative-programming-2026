Why visualise?

  • Numbers alone are hard to interpret
  • Visualisation reveals patterns, trends, and outliers
  • It makes data accessible and engaging
  • In creative programming, the visual IS the output

Visualisation in the real world

The core idea

This is the most important concept of the lecture. Data visualisation is about mapping values to visual properties. You already know map() from earlier weeks — here it becomes the main tool. Every chart type in this lecture is just a different way of mapping data to shapes, positions, sizes, colours, and angles.

  • Data visualisation = mapping values to visual properties
  • map() is the key function for this
  • One data value can drive one or more visual properties:
    • Position: x, y
    • Size: width, height, diameter
    • Colour: r, g, b, alpha
    • Angle: rotation, arc size

The building blocks

Every chart is built from the same primitives you have been using all semester. The only new idea is that these properties are driven by data values instead of being hard-coded. No new functions needed!

  • Every chart is built from things we already know
    • Shapes: rect(), circle(), line(), image()
    • Position: x, y coordinates
    • Colour: fill(), stroke()
    • Text: text(), labels, titles
  • The difference: these properties are driven by data

Bar charts

The idea is to loop through an array and draw a rect() for each value. The height of each bar is proportional to the data value, scaled to fit the canvas. This is the simplest chart type and a good place to start.

  • Each bar represents a category, the height represents a value
  • Loop through an array and draw a rect() per value
  • Labels and values are drawn with text()

Key formula: positioning bars

This formula works for any number of bars. The i * (barWidth + spacing) part spaces them out evenly. Drawing from bottomY - barHeight makes bars grow upward from the bottom, which is what we expect in a chart.

  • Calculate each bar’s x position:
let x = startX + i * (barWidth + spacing);
  • Draw from the bottom up:
let barHeight = values[i] * scale;
rect(x, bottomY - barHeight, barWidth, barHeight);

Adding colour as a second dimension

Here, map() turns data values into colour components, so higher values appear warmer and lower values appear cooler. This adds a visual dimension without adding complexity — the viewer gets two pieces of information from the same bar.

  • Use map() to convert values into colours
  • Higher values = warmer colours, lower values = cooler colours

Key concept: flipping y

This trips up a lot of people. Remember that in p5.js, y = 0 is the top of the canvas. In charts we want higher values to appear higher on screen, so we reverse the output range in map(). If your chart looks upside down, this is probably why.

  • In p5.js, y = 0 is the top of the canvas
  • In charts, higher values should be higher on screen
  • map() handles this by reversing the output range:
let y = map(value, 0, maxVal, bottomY, topY);
//                              high y → low y

Line charts

Line charts use line() segments between consecutive data points. Grid lines help the viewer estimate values. Line charts are best for showing trends over a sequence like time.

  • Shows how values change over a sequence (often time)
  • Draw line() segments between consecutive data points
  • map() converts values to screen positions

Chart design tips

  • Always label your axes and add a title
  • Use colour purposefully, not decoratively
  • Start bar charts at zero to avoid misleading proportions
  • Keep it simple: one chart, one message
  • Use textAlign() to position labels cleanly

More Charts and Techniques

Hover detection for charts

These are the same collision patterns from earlier lectures, just applied to chart elements. For bars you check a bounding box, for dots you check distance. Nothing new here, but worth keeping in mind as you build your visualisations.

  • For chart interactivity, hover detection is really neat!
  • It can be useful for long conditions to store them in a variable for readability
// For rectangles (bars):
let isHovered = mouseX > x && mouseX < x + barWidth &&
                mouseY > barTop && mouseY < bottomY;

// For circles (scatter plots):
let isHovered = dist(mouseX, mouseY, cx, cy) < radius;
  • The dist() function calculates the distance between two points

Scatter plots

Each data point has two values that get mapped to x and y positions. This example includes hover detection using dist() — when the mouse is close enough to a point, extra info appears. Try hovering over the dots to see it in action.

  • Shows the relationship between two variables
  • Each point has an x and a y value mapped to canvas positions
  • Great for seeing correlations and clusters

Pie charts

The arc() function in PIE mode draws each slice. Each value is converted into an angle proportional to its share of the total. The angles accumulate so each slice starts where the previous one ended. Placing labels uses cos() and sin() to calculate positions from the angle — the same trigonometry from earlier weeks.

  • Shows parts of a whole as slices of a circle
  • Use arc() with PIE mode to draw each slice
  • Angles accumulate so slices connect seamlessly

Key formula: values to angles

  • Remember to set angleMode(DEGREES) in setup()!
let total = 0;
for (let i = 0; i < values.length; i++) {
  total += values[i];
}

let sliceAngle = map(values[i], 0, total, 0, 360);
  • The full circle is 360 degrees
  • Each slice gets a fraction of the circle

A word of caution on pie charts

Pie charts are one of the most recognisable chart types, but they are actually quite hard to read when there are more than two slices. Human eyes are bad at comparing angles and areas — it is much easier to compare bar heights. A pie chart works well for showing something like “60% yes, 40% no”, but for anything more complex, a bar chart is almost always a better choice.

  • Pie charts look nice, but they are hard to read with many slices
  • Human eyes are bad at comparing angles and areas
  • Works well for two categories (e.g. 60% vs. 40%)
  • For 3+ categories, a bar chart is almost always clearer

Multiple mappings

In this example, each circle represents a Danish city. Position shows area and population, size also shows population, and colour intensity does too. This is called multi-dimensional mapping — one data point drives multiple visual channels. It can be very effective, but be careful not to overdo it.

  • One data point can drive multiple visual channels
  • Example: position, size, AND colour from the same dataset
  • Be careful not to overdo it

Animating charts with lerp

This is the same lerp() easing from earlier lectures, applied to chart data. Each frame, the current bar height moves a fraction closer to the target. Click the sketch to reset and watch the animation again.

  • We have used an easing formula before, but you can also use lerp()
  • Use either to smoothly transition bar heights from zero
currentHeight = lerp(currentHeight, targetHeight, 0.03);

The arrays grow with each click and the chart redraws itself every frame to accommodate the new data. This pattern is useful for user-driven data collection or for building up a visualisation step by step.

Infographics

What is an infographic?

An infographic combines multiple visual elements into one layout that tells a complete story. Think of it as a poster for your data. The skill is combining chart types and techniques you already know into a clear, attractive composition.

  • A visual summary that combines multiple elements into one layout
  • Charts + icons + key numbers + text + colour
  • Tells a complete story at a glance
  • Common in journalism, reports, social media, and public health

Pictogram charts

A pictogram replaces abstract bars with repeated icons. Each icon represents a fixed number of units, which makes the data more tangible and engaging. In the example, simple person-shaped icons are drawn using circles and rectangles. The key design decision is how many units each icon represents.

  • Replace bars with repeated icons to represent quantities
  • Each icon = a fixed number of units
  • More engaging and intuitive than abstract bars

Progress and gauges

Circular gauges use arc(), progress bars use rect(). The key is converting a percentage into an angle or width. These are the same functions as in the pie chart, just styled differently. Combined with lerp() animation they feel quite polished.

  • Show progress toward a goal (current vs. target)
  • Circular gauges use arc(), progress bars use rect()
  • Great for dashboards and tracker-style layouts

Key formula: circular gauge

Starting at -90 puts the beginning of the arc at the 12 o’clock position, which is what you would expect for a gauge. It is the same arc() function as in pie charts, just styled differently.

  • Same idea as pie charts — remember angleMode(DEGREES)!
let pct = current / target;        // 0.0 to 1.0
let endAngle = -90 + 360 * pct;   // start from top

// Background ring
arc(cx, cy, size, size, -90, -90 + 360);

// Filled ring
arc(cx, cy, size, size, -90, endAngle);
  • -90 starts the arc at the top (12 o’clock)

Composing an infographic

This example combines a header, summary stat boxes, a line chart, and a bar chart in one canvas. The trick is to divide the canvas into regions and draw each component within its own area. It helps a lot to sketch the layout on paper before writing any code.

  • Divide the canvas into regions (header, stats, charts)
  • Draw each component in its own region
  • Use consistent colours and typography throughout

This example pulls live data from the Open-Meteo API for four Danish cities. No API key is needed, so you can try this yourself! It shows current conditions as stat cards, a 7-day forecast as a multi-line chart, and current wind speed as bars. The data is different every time you load the sketch — that is the fun part of working with live APIs.

  • Fetches live weather for Copenhagen, Aarhus, Odense, and Aalborg
  • Uses the Open-Meteo API from last lecture
  • Combines stat cards, line chart, and bar chart in one dashboard

Infographic design tips

  • Hierarchy: biggest/boldest element = most important message
  • Consistency: pick 3-4 colours and stick with them
  • White space: don’t fill every pixel — let the layout breathe
  • Flow: guide the eye from top to bottom, left to right
  • Source: always credit your data source
